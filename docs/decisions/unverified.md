# Unverified-facts register

One row per fact that the plan could not check. Built from every "Unverified items to check" table in sections
[A](../plan/A-repository-findings.md#unverified-items-to-check) to [J](../plan/J-execution-backlog.md#unverified-items-to-check), the
**[UNVERIFIED]** labels in the [spine](../plan/00-spine.md) and in [build-phases.md](../build-phases.md) that name a check, and two
open points from ADRs and the DNS runbook. A fact listed in several sections has one row that links every source.
J task M0-14, Phase 5.

**How rows are ticked** ([J §J.1.3](../plan/J-execution-backlog.md#j13-definition-of-done-for-every-task-proposal) rule 5):

- The task that settles a row writes the result in its ADR, release entry or runbook. In the same commit, the row's Status
  changes to `settled <date>` with the result and a link to that evidence.
- If the result changes a plan decision, the ADR records it; the row only points to it.
- Rows are never deleted or renumbered. A new unverified fact gets the next free `U-` number.
- "Settled by" is the build phase ([build-phases.md](../build-phases.md#overview-of-all-phases)) and J task that owns the check.

Source keys: A–J = that plan section's "Unverified items to check" table; S = spine; BP = build-phases.md; text anchors are given
where a section also labels the fact in its body.
