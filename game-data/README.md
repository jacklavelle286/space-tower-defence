# game-data

Versioned game data ([spine S5.1](../docs/plan/00-spine.md#s51-pins-and-game-data), [C §C15](../docs/plan/C-game-and-learning-design.md#c15-where-these-numbers-live-in-the-build)). Phase 13 (M1-23) added the first files.

| Path | What | Published at |
|---|---|---|
| `ruleset/<version>.json` | One ruleset: `mechanics`, colony, classes, aliens, economy, caps | `/game-data/ruleset/<version>.json` |
| `campaign/<version>.json` | One planet document: map, pads, authored waves, `waveSets` | `/game-data/campaign/<version>.json` |
| `current.json` | The versions new runs use | `/game-data/current.json` |
| (generated) | The bounds file for the pair `current.json` names | `/game-data/bounds/<ruleset>__<campaign>.json` |

Rules:

- **Add, never edit.** A run pins its versions, and the release uploads every versioned file create-only. Re-uploading
  the same bytes is fine; a published file with different bytes stops the release. To change the game, add a new
  version and point `current.json` at it. `current.json` is the only file that is overwritten.
- Versions match `^[a-z0-9.-]{1,40}$`, and each file's `version` field equals its file name.
- A change to a *rule* (not a number) needs a new `mechanics` number, and `game-core` must support it first
  (`SUPPORTED_MECHANICS` in `web/game-core/src/data/game-data.ts`).
- Rulesets so far: `r1` (mechanics 1, Phase 13: Nova only) is the one `current.json` names; `r2` (mechanics 2, Phase 24:
  the six-class roster, plus the slow rules Phase 25 added) is not used for new runs until the Phase 25 gate
  ([ADR-0033](../docs/decisions/0033-ruleset-r2-mechanics-2-roster.md)). Try it locally at
  `/play/local?ruleset=r2&roster=all&credits=2000` (`npm run dev -w player`). `r3` (mechanics 3, Phase 26: r2 plus the
  ten aliens of C6.1 with their traits as data; a planet document may name a carrier's `cargo` under it) is not used
  for new runs either ([ADR-0034](../docs/decisions/0034-ruleset-r3-mechanics-3-aliens.md)). Watch every alien at
  `/play/local?ruleset=r3&roster=all&credits=3000&aliens=all` (or `aliens=craft:2,slime:3`). Phase 27 added the five
  bosses of C7 to r3 (`bosses`, before r3 was published; still mechanics 3, ADR-0034 amended). Watch one at
  `/play/local?ruleset=r3&roster=all&credits=5000&boss=boss3` (or `boss=all` for one wave per boss). Phase 28 added the
  three meteor powers of C10 to r3 (`powers`, and the use rules in `powerRules`; still mechanics 3, ADR-0034 amended again).
  Try them at `/play/local?ruleset=r3&roster=all&credits=5000&boss=boss1&powers=all`: keys 1, 2 and 3 during a wave.
- Numbers come from the balance simulator (`tools/sim/game_data.json`). `web/game-core/src/data/sim-agreement.test.ts`
  checks every one of them.
- The bounds file is generated by `web/game-core/scripts/build-bounds.ts`. Never write one by hand.

Check from `web/`: `node game-core/scripts/build-bounds.ts --check` runs gate G-15 (every wave set fits in 100
create-run actions), every parse rule, and the bounds-fixture check. If you change the current pair, run
`node game-core/scripts/build-bounds.ts --write-fixture` to refresh `contracts/fixtures/bounds/`, which `api/tests` reads.
